# Закупки ekt.kz — AI-планировщик закупок

**Загрузите выгрузки из 1С — получите готовый заказ поставщику с обоснованием по каждой позиции.**

Сервис сам считает, что и сколько дозаказать по каждому SKU: очищает спрос от разовых всплесков, учитывает сезонность, тренд, товар в пути, страховой запас и кратность упаковки — и объясняет каждую строку. Менеджеру остаётся проверить, поправить и выгрузить заказ в Excel.

## Зачем это

Закупщик вручную сводит десяток отчётов по каждому поставщику, чтобы понять, что заканчивается. Это долго и субъективно. Наш сервис:

- **считает заказ автоматически** — прогноз спроса на горизонт «срок поставки + период между заказами», минус остаток и товар в пути, с округлением до кратности упаковки;
- **объясняет каждую цифру** — очищенный спрос, сезонный коэффициент, тренд, страховой запас — видно, почему рекомендовано именно столько;
- **подсвечивает срочное** — позиции, которые вот-вот закончатся, отмечаются приоритетом;
- **держит менеджера у руля** — разовые крупные продажи можно исключить из спроса, любое количество — поправить с указанием причины;
- **отдаёт результат в 1С** — утверждённый заказ выгружается в Excel-файл.

Работает с двумя поставщиками — **Systeme Electric** и **IEK**. Можно загрузить одного или обоих.

## Быстрый старт (Docker)

Нужен только Docker с плагином Compose. Из корня репозитория:

```bash
docker compose up --build
```

Откройте **http://localhost:8081** — фронтенд и backend поднимаются вместе, `/api/*` проксируется на backend автоматически.

| Сервис | Что это | Адрес |
| --- | --- | --- |
| `frontend` | React + Vite за nginx | http://localhost:8081 |
| `backend` | Spring Boot, разбор Excel и расчёт заказов | http://localhost:8080 |

Остановить: `docker compose down`.

## Как это работает

1. **Загрузка** — перетащите отчёты (по 6 на поставщика: динамика продаж, ежемесячные продажи и остатки, товар в пути, сезонность, кратность). Поставщик и тип определяются по имени файла; можно грузить одного поставщика или обоих.
2. **План заказа** — сервис показывает рекомендованный заказ: сводка, вкладки по поставщикам, фильтр срочности, поиск. Клик по строке открывает карточку с пошаговым обоснованием.
3. **Утверждение** — правите количества при необходимости и нажимаете «Утвердить» → скачивается Excel-файл заказа для 1С.

## Как устроено

| Слой | Технологии |
| --- | --- |
| Frontend | React 19, TypeScript, Vite, TanStack Query |
| Backend | Spring Boot + Kotlin, Java 21, Gradle |
| Обмен | REST + `multipart/form-data`, данные хранятся в памяти backend |

### Запуск без Docker

**Backend** (нужен JDK 21, Gradle не требуется — wrapper в проекте):

```bash
./gradlew bootRun      # http://localhost:8080
```

**Frontend** (нужен Node.js 20+):

```bash
cd frontend
npm install
npm run dev            # http://localhost:5173, работает на моках
```

Фронтенд по умолчанию работает на моках (бэкенд не нужен). Чтобы ходить в настоящий backend: `VITE_USE_MOCKS=false BACKEND_URL=http://localhost:8080 npm run dev`.

## API

| Запрос | Назначение |
| --- | --- |
| `POST /api/excel` | Загрузка отчётов (`multipart/form-data`, поля `iekMoq`, `systemeSalesDynamics`, …). Поставщик — все 6 отчётов либо ни одного; хотя бы один обязателен. Возвращает счётчики записей и замечания к ячейкам. |
| `GET /api/orders` | Рекомендованный заказ по последней загрузке. Обязательные `leadDays` и `reviewDays`; опционально `historyMonths`, `forecastGrowthPercent`, `supplierId`, `category`. |

Подробности: контракт расчёта, формулы и ограничения — в [docs/order_calculation.md](docs/order_calculation.md); типизированные модели Excel — в [docs/excel_models.md](docs/excel_models.md); экраны и сценарии фронтенда — в [frontend/README.md](frontend/README.md).

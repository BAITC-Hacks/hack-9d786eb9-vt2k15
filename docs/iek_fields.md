# IEK: полный словарь полей Excel

Проверены все 6 файлов из `task spec/IEK`, каждый XLSX прочитан как ZIP/XML без изменения и пересчёта. Словарь перечисляет все непустые колонки всех настоящих листов, отдельные смысловые блоки сезонности и встроенный кэш внешнего прайса. Сохранённое значение формулы обозначено как кэш; оно не является результатом нового пересчёта.

Технический инвентарь: [iek_fields.json](iek_fields.json). В нём сохранены SHA-256 каждого исходника, состояния листов, размеры, скрытые строки, объединения, точные заголовки с координатами, отдельное описание каждого месячного столбца, количество значений и формул, примеры формул и ошибок. Поля JSON `recommended_db_type` и `meaning` — предлагаемая интерпретация; `headers`, `primary_source_name`, `source_name` и значения — наблюдения из источника. Для многострочных шапок использовать весь массив `headers`, а не одно короткое имя.

Ошибку нельзя превращать в ноль или MOQ=1. 1938 товарных строк содержат 1937 уникальных кодов, `270400035_` повторяется. Артикулы также не гарантированно уникальны.

## Связи и ограничения для схемы БД

Общий ключ основных таблиц — текстовый код 1С: MOQ.B = Динамика.D = Остатки.C = Месячные продажи.B = Путь.A. Артикул поставщика — отдельное поле (MOQ.C = Путь.B), которое связывает записи с внешним прайсом A. Ведущие нули, буквы и завершающий `_` сохраняются. Номер строки/название товара не являются ключами.

Не все источники имеют один набор товаров. Из 2463 кодов месячных продаж 702 отсутствуют в MOQ, 379 — в файле пути, 7 — в месячных остатках. Нужны явные статусы несопоставленных строк и политика дубликатов; `INNER JOIN` потеряет товары.

При нормализации сохранять происхождение: файл и SHA-256, лист, номер исходной строки/ячейки, исходное значение, формулу и её кэш, ошибку ячейки, дату снимка/период. Для месячных колонок хранить месяц как дату первого числа, для сезонности — год и номер месяца. Итоговые колонки и строки — контрольные показатели источника, а не дополнительные факты.

В шести настоящих листах IEK отсутствуют отдельные поля клиента, нормативного lead time, резерва, текущего свободного остатка, ежедневных остатков/дней stockout и управленческой категории. Даты прибытия партий не заменяют нормативный lead time. Эти значения нельзя выводить из похожих названий автоматически; их нужно получить отдельно либо явно хранить как предположения модели.


Проверка покрытия: для каждого настоящего листа сумма непустых ячеек описанных полей, шапок, подписей и итогов сверена с полным XML-сканированием. Неучтённых непустых ячеек — **0** во всех шести листах; результаты по листам записаны в `coverage_check` JSON. SHA-256 исходных XLSX после анализа совпадают с первоначально сохранёнными: Excel не изменялись. Это проверка инвентаризации, а не проверка правильности бизнес-формул.

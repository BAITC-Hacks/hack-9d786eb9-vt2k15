# Словарь исходных данных и модель хранения

Проверка исходных Excel: 23.09.2026. Этот документ описывает данные для импорта и предлагает логическую модель БД. Он не создаёт таблицы и не загружает данные. Исходные Excel не изменены.

## Как пользоваться

- [IEK: поля каждого файла и листа](./iek_fields.md).
- [Systeme Electric: поля каждого файла и листа](./systeme_fields.md).
- [IEK: техническая инвентаризация JSON](./iek_fields.json).
- [Systeme Electric: техническая инвентаризация JSON](./systeme_fields.json).

В отдельных словарях приведены исходные заголовки, координаты, блоки, примеры, формулы и оговорки. Повторяющиеся месячные колонки в текстовых таблицах могут объединяться в диапазоны; техническая инвентаризация сохраняет точные адреса и заголовки. Пустые оформленные ячейки сами по себе не являются полями.

Поля ниже с английскими именами — **предложение для БД**, а не существующие названия Excel. Технические ID, даты загрузки, источник и статусы добавляет приложение. Значения, которых нет в источнике, не следует заполнять догадками.

## 1. Что означает «взять всё»

Удобны два слоя хранения:

1. **Исходный слой:** оригинальный XLSX и его хеш, листы, координаты, исходные значения, ошибки и формулы. Он позволяет вернуться к первоисточнику и перепроверить импорт.
2. **Предметные таблицы:** товары, продажи, остатки, поставки, условия заказа и сезонность. Их использует расчёт закупки.

Итоги Excel, повторная копия месячных продаж в сводном шаблоне, формулы и внешние кэши не должны становиться дополнительными продажами. Сохранить значение и включить его в расчёт — разные действия.

## 2. Общие типы и ключи

| Данные | Рекомендуемый тип | Правило |
| --- | --- | --- |
| Код 1С, артикул, номер документа, код категории | `TEXT` | Сохранять ведущие нули, символ `_`, буквы и исходное значение. Номер документа не уникален сам по себе. |
| Наименование, склад, единица, исходный заголовок | `TEXT` | Не использовать наименование как ключ. Сокращения без расшифровки сохранять буквально. |
| Количество, остаток, партия, кратность | `DECIMAL(24,6)` | Дробные единицы допустимы. Не ограничивать все количества целыми числами. Точность — проектный выбор; превышение должно давать ошибку импорта, а не незаметное округление. |
| Стоимостное значение | `DECIMAL(24,6)` | Валюта и способ оценки отдельными полями; неизвестную валюту оставлять `NULL`. |
| Коэффициент, доля, покрытие | `DECIMAL(24,10)` | Отделять относительное изменение от множителя и доли. Например, рост `0.2` — это +20%, множитель `1.2` — другая величина. |
| Месяц | `DATE` | Первый день месяца, например `2026-09-01`. Полнота периода хранится отдельно. |
| Дата поступления/снимка | `DATE` | Отделять явно заданную дату от выведенной из имени файла/заголовка. |
| Дата-время операции | `TIMESTAMP` | Не назначать UTC без знания часового пояса источника. Если источник содержит только дату, точность времени должна это отражать. |
| Формула, ошибка Excel | `TEXT` | Хранить формулу и кешированное значение раздельно. `#N/A` не равно нулю. |
| Технические метаданные | `JSON` | Для исходного слоя и параметров расчёта; основные факты хранить типизированными колонками. |

Бизнес-ключ товара в текущем наборе — код 1С компании «Электрокомплект». Для расширяемой схемы: `UNIQUE(company_id, erp_code)`. `company_id` задаёт пространство кодов компании, а не поставщика. Артикул поставщика хранится отдельно и не предполагается глобально уникальным.

Имя папки IEK / Systeme electric даёт метку набора поставщика/бренда, но не полное юридическое наименование контрагента и не его реквизиты. Это происхождение метки следует сохранить.

## 3. Исходный слой без потерь

| Таблица | Поля | Смысл и ключ |
| --- | --- | --- |
| `import_batches` | `id`, `imported_at`, `parser_version`, `status` | Одна попытка загрузки. |
| `source_files` | `id`, `import_batch_id`, `source_path`, `file_name`, `sha256`, `supplier_label`, `report_as_of_date`, `as_of_date_basis`, `original_file_uri` | Одна версия файла. Дата отчёта может быть неизвестна; не подменять её временем изменения файла. |
| `source_sheets` | `id`, `source_file_id`, `sheet_name`, `sheet_state`, `declared_dimension`, `nonempty_bounds` | Лист, включая скрытые. Ключ `(source_file_id, sheet_name)`. |
| `source_cells` | `source_sheet_id`, `row_number`, `column_number`, `cell_ref`, `cell_type`, `raw_value`, `formula_text`, `cached_value`, `error_code`, `number_format` | Исходные непустые ячейки и ячейки с формулой. Ключ `(source_sheet_id, cell_ref)`. Пустые ячейки восстанавливаются из структуры листа; пустой ввод не превращать в число 0. |
| `import_issues` | `id`, `source_sheet_id`, `cell_ref`, `issue_code`, `raw_value`, `message`, `resolution_status` | Пропущенный код, ошибка Excel, конфликт единиц, неоднозначная дата и другие проблемы импорта. |

Допустим более компактный вариант `source_rows(cells_json)` вместо таблицы каждой ячейки, если JSON сохраняет координаты, типы, формулы, кеш и ошибки. Сам оригинальный XLSX нужен для сохранения объединённых ячеек, оформления, внешних связей и прочих структур, которые не входят в предметную БД.

Ссылка на источник у предметной записи: `source_sheet_id` и `source_row_number`, а для развёрнутых месячных/поставочных колонок ещё `source_cell_ref`. Если результат собран из нескольких ячеек, хранить несколько ссылок в отдельной таблице происхождения или JSON-списке.

## 4. Справочники

| Таблица | Поле | Значение / откуда брать |
| --- | --- | --- |
| `products` | `id` | Внутренний ID. |
| | `company_id`, `erp_code` | Пространство учёта и исходный код 1С. |
| | `name` | Наименование из источника. Альтернативные исходные наименования сохраняются в исходном слое. |
| | `base_unit` | Единица складского учёта из остатков/динамики, если присутствует. Не выводить её автоматически из названия. |
| `suppliers` | `id`, `source_label`, `legal_name` | Метка IEK / Systeme electric известна из набора; юридическое имя пока неизвестно. |
| `supplier_products` | `id`, `supplier_id`, `product_id`, `supplier_article`, `source_sheet_id`, `source_row_number` | Соответствие товара артикулу поставщика. Нужна обработка дублей и конфликтов, а не выбор первой строки. |
| `product_categories` | `product_id`, `category_code`, `category_year`, `source_sheet_id`, `source_row_number` | `Категория 2026` в сводной таблице Systeme. Это исходный код категории, не вычисленный ABC/XYZ. |
| `warehouses` | `id`, `name_raw`, `name_normalized` | Склад из динамики. Компоненты запасов шаблона не приравнивать к отдельным складам без подтверждения. |
| `supplier_order_terms` | `supplier_product_id`, `term_kind`, `quantity`, `unit`, `as_of_date`, `source_sheet_id`, `source_cell_ref` | Для Systeme поле «Кратность» даёт `order_multiple`. Для IEK «Мин. разр. к отгр.» сохранять как `minimum_shipment_raw` до подтверждения смысла. |

Если бизнес подтвердит, что IEK-поле означает минимальную партию, можно сопоставить `minimum_order_qty`; если кратность — `order_multiple`. Минимум 10 и кратность 10 не тождественны: минимум допускает 11, кратность — нет. Нельзя заполнять оба параметра одним числом без подтверждения.

Закупочная единица может отличаться от складской. Для неё нужна отдельная, подтверждённая связь `product_unit_conversions(product_id, from_unit, to_unit, factor, valid_from, source)`. В IEK встречается примечание о закупке кабеля бухтами при учёте в метрах; полную таблицу коэффициентов исходные файлы не дают.

## 5. Продажи

### `sales_document_lines` — строка исходного документа

| Поле | Тип | Источник / объяснение |
| --- | --- | --- |
| `id` | ID | Технический ключ строки. |
| `product_id` | ID | По колонке «Код». |
| `operation_at` | `TIMESTAMP` | «Дата», с сохранением исходной точности. |
| `document_number` | `TEXT` | «Номер». |
| `document_raw` | `TEXT` | Полная строка «Документ», включая тип, номер и дату. |
| `document_type` | `TEXT`, nullable | Разобранный из `document_raw` тип: расходная/приходная накладная, заказ покупателя и т. п. Это результат парсинга, не отдельная колонка исходника. |
| `product_name_raw` | `TEXT` | «Номенклатура». |
| `unit_raw` | `TEXT` | «Ед.». |
| `warehouse_id`, `warehouse_name_raw` | ID / `TEXT` | «Склад». |
| `quantity_signed` | `DECIMAL(24,6)` | «Количество» с исходным знаком. |
| `source_sheet_id`, `source_row_number` | ID / integer | Уникальность строки внутри версии источника. |

Не объявлять сочетание `(document_number, product_id)` уникальным: в документе могут повторяться строки. Для повторных выгрузок необходима отдельная стратегия дедупликации; совпадение номера документа недостаточно. Тип документа и знак количества должны участвовать в классификации продажи/возврата/другой операции. Не инвертировать все знаки и не превращать отрицательные значения в ноль при загрузке.

### `sales_monthly` — количество за месяц

| Поле | Тип | Источник / объяснение |
| --- | --- | --- |
| `product_id` | ID | Код товара в строке. |
| `month` | `DATE` | Год и месяц из заголовка; по одной записи на каждую месячную ячейку. |
| `quantity_signed` | `DECIMAL(24,6)` | Исходное значение, включая отрицательные корректировки. |
| `warehouse_id` | ID, nullable | Только если склад явно задан. Отсутствие склада не означает автоматически «Алматы». |
| `scope_raw` | `TEXT` | Область отчёта/набора, если известна. |
| `period_status` | `TEXT` | `complete`, `partial` или `unknown`; хранить основание. |
| `period_cutoff_date`, `period_status_basis` | `DATE` / `TEXT` | Например, подтверждённая дата среза. Имя файла не всегда содержит её. |
| `source_sheet_id`, `source_cell_ref` | ID / `TEXT` | Идентификатор исходного наблюдения. |

Не создавать колонки БД `january_2024`, `february_2024` и т. п. Развернуть их в строки `(product_id, month, quantity_signed)`.

Месячная выгрузка, месячные колонки `TDSheet` и агрегация динамики — **альтернативные наблюдения**, а не три слагаемых. Сначала хранить их с разными источниками. После сверки выбрать один источник на область/период для расчёта. Исходные итоги «Итого»/годовые суммы сохранять для проверки, но не добавлять к месячным фактам.

## 6. Остатки

### `stock_monthly` — историческое наблюдение

Поля: `product_id`, `month`, `quantity`, `unit_raw`, `balance_kind`, `warehouse_id` (nullable), `scope_raw`, `source_sheet_id`, `source_cell_ref`.

`balance_kind` указывает начало/конец периода/неуточнённый снимок. Для IEK заголовок подтверждает начальный остаток; для Systeme в месячной таблице момент измерения не установлен. Для начального остатка месяца дата — первое число месяца. Нельзя интерпретировать колонку «Итого» как сумму запасов разных месяцев. Из нулевого месячного остатка нельзя получить точное число дней отсутствия товара.

### `inventory_snapshot_components` — компоненты текущего снимка

Поля: `product_id`, `snapshot_date`, `snapshot_date_basis`, `component_code`, `component_label_raw`, `quantity`, `unit_raw`, `warehouse_id` (nullable), `source_sheet_id`, `source_cell_ref`.

В `TDSheet` Systeme наблюдаются:

| Колонка | Исходное поле | `component_code` | Смысл |
| --- | --- | --- | --- |
| AT | Витрина | `display_stock` | Значение отдельного компонента. Доступность для продажи уточняется. |
| AU | Остаток ТЗ | `tz_stock` | Сокращение «ТЗ» не расшифровано в файле. |
| AV | РЦ ЕКТ  Рыскулова | `ryskulova_dc_stock` | Отдельный компонент, названный в источнике. |
| AW | Розничный склад | `retail_stock` | Отдельный компонент. |
| AX | Остаток | `stock_raw` | Остаток в сводной таблице; охват других компонентов требует подтверждения. |
| AY | Зарезервировано | `reserved_stock` | Зарезервированное количество. |
| AZ | Свободный остаток | `free_stock` | Свободное количество из исходного шаблона. |

Не складывать автоматически AX + AZ или все компоненты. «Остаток» и «Свободный остаток» могут описывать одну совокупность до/после резерва. Формула покрытия Excel включает некоторые компоненты и не включает AV — это поведение шаблона, а не подтверждение независимости всех запасов.

## 7. Ожидаемые поставки

### `incoming_shipments`

| Поле | Тип | Источник / объяснение |
| --- | --- | --- |
| `id`, `supplier_product_id` | ID | Технический ключ и связь с товаром поставщика. |
| `snapshot_date`, `snapshot_date_basis` | `DATE` / `TEXT` | Дата отчёта о поставках, отдельно от даты прибытия. |
| `shipment_label_raw` | `TEXT` | Полный исходный заголовок партии. |
| `supplier_order_number` | `TEXT`, nullable | Номер заказа, если он указан в заголовке. |
| `supplier_order_date` | `DATE`, nullable | Дата после «от» в заголовке партии IEK. Это дата документа заказа, не дата получения товара. |
| `order_prefix_raw` | `TEXT`, nullable | Префикс вроде «РФ» или «ПП»; расшифровка не задана. |
| `expected_date_from`, `expected_date_to` | `DATE`, nullable | Ожидаемая дата или диапазон. При точной дате оба значения равны. |
| `expected_date_kind` | `TEXT` | `on`, `range`, `by_deadline` или `unknown`. «Поступление до 10.10.2026» задаёт верхнюю границу, а не точный день прибытия. |
| `date_parse_basis` | `TEXT` | Например: год взят из даты отчёта; требует проверки. |
| `quantity` | `DECIMAL(24,6)` | Ячейка количества товара в конкретной партии. |
| `unit_raw` | `TEXT`, nullable | Если единица не указана, не угадывать. |
| `source_sheet_id`, `source_cell_ref` | ID / `TEXT` | Исходная ячейка. |

Шесть колонок партий IEK преобразуются в несколько строк поставок. Для заголовка «поступление до …» заполнять `expected_date_to`, оставляя начало неизвестным. Systeme `BC «СЭ в пути 24.09»` — другой источник этого же вида факта. Заголовок `24.09` не содержит года; 2026 можно вывести из имени файла, сохранив это как интерпретацию, а не явно записанный факт. Назначение даты `24.09` также желательно подтвердить у владельца отчёта.

Нулевые и пустые ячейки сохраняются различимыми в исходном слое. Для рабочего списка можно выбрать только подтверждённые ненулевые ожидаемые количества. Дата ожидаемой партии не равна нормативному сроку поставки.

## 8. Себестоимость, вес и исходные расчёты

### `product_snapshot_attributes`

Поля: `product_id`, `snapshot_date`, `attribute_code`, `source_label`, `numeric_value`, `text_value`, `unit`, `currency_code`, `source_sheet_id`, `source_cell_ref`.

- `F «СС реал»` — стоимостное поле. По контексту вероятна себестоимость, но источник не задаёт полностью её методику, валюту и налоговый состав. Сохранить под кодом `ss_real_raw`, не использовать автоматически как цену продажи.
- `BH «Вес»` — заголовок поля, обнаруженный за основной таблицей. Пустое поле всё равно присутствует в структуре; единицу веса не выводить автоматически.

### `source_calculated_metrics`

Поля: `product_id` (nullable для общих итогов), `source_sheet_id`, `source_cell_ref`, `metric_code`, `source_label`, `period_start`, `period_end`, `formula_text`, `cached_value`, `error_code`, `unit`, `calculation_note`.

Основные расчётные колонки `TDSheet`:

| Колонка | Исходное название | Предлагаемый код | Объяснение |
| --- | --- | --- | --- |
| S | Продажи 2024 | `sales_2024_total_source` | Сумма месяцев 2024. |
| T | Ср мес 2024 | `sales_2024_monthly_avg_source` | Годовая сумма / 12. |
| AP | Сумма последние 12 мес | `trailing_sales_total_source` | В проверенной формуле суммируются 13 месяцев: сентябрь 2025 — сентябрь 2026. Сохранить формулу как есть и отметить несоответствие заголовку. |
| AQ | Ср мес за последние 12 мес | `trailing_monthly_avg_source` | Обычно AP / 12; исключение `AQ485 = AP485/5`. Наследует проблему периода и содержит отдельное правило строки, смысл которого нужно уточнить. |
| AR | Кэф. Роста | `growth_change_source` | Относительное изменение июня–августа 2026 к июню–августу 2025. Это значение «отношение − 1». |
| AS | Кэф. Сез-ти | `seasonal_change_source` | Относительное изменение сентября–ноября 2025 к июню–августу 2025. Это не готовый положительный множитель. |
| BA | Запас | `coverage_months_source` | Расчёт покрытия в месяцах по формуле шаблона. Это не количество товара. |
| BB | Заказ | `order_quantity_source` | Место ввода заказа. В текущем шаблоне пустое; не трактовать как рассчитанный нулевой заказ. |

Отрицательное относительное изменение AR/AS может означать снижение. Его нельзя само по себе объявить ошибкой только из-за отрицательного знака. Если знаменатель/числитель содержат возвраты или малые значения, интерпретация требует отдельной проверки.

В строке 485 отсутствуют формулы S/T, которые есть в остальных строках. Поэтому тип колонки «формула» не означает, что каждая её ячейка заполнена одинаково. В текущих 497 строках `AX − AY = AZ`; это подтверждает арифметическую связь этих трёх полей, но не раскрывает охват остальных складских компонентов.

## 9. Общая сезонность

Листы сезонности содержат несколько отдельных таблиц, а не перечень SKU. В одной и той же физической колонке на разных строках могут находиться сумма, среднее и коэффициент — их нужно импортировать по блоку.

### `seasonality_observations`

Поля: `id`, `supplier_id`, `scope_type`, `scope_key`, `year` (nullable), `month_number`, `metric_kind`, `numeric_value`, `unit_raw`, `formula_text`, `cached_value`, `value_status`, `source_sheet_id`, `source_cell_ref`.

Типы показателей определяются конкретным блоком словаря: месячный агрегат, итог года, среднее, коэффициент внутри года, доля месяца, усреднённый/нормализованный сезонный коэффициент, вспомогательный коэффициент. Для годового итога `month_number` может быть `NULL`. Не придумывать SKU для агрегата по поставщику.

Единица общей суммы не всегда подтверждена заголовком. До уточнения сохранять исходное название и `unit_raw = NULL`, не объявлять её выручкой или количеством. Прогнозные/достроенные значения и наблюдаемые месяцы отмечать раздельно; формула сама по себе ещё не означает прогноз.

Копии сезонных блоков в разных книгах сохраняются с разными источниками. Выбор рабочего профиля — отдельная настройка, а не суммирование всех копий.

## 11. Правила импорта, которые предотвращают потерю смысла

1. Проверять коды, типы, единицы и версии файлов до объединения. Строки с отсутствующим ключом оставлять в исходном слое и списке проблем.
2. Делать объединение с отчётом о несовпадениях. Не терять товары из-за `INNER JOIN` на неполный MOQ или шаблон закупки.
3. Различать ноль, пустую ячейку, ошибку Excel, отсутствие строки и недоступное вычисление.
4. Отделять строки товаров от заголовков, итогов, примечаний и сезонных агрегатов.
5. Разворачивать месяцы и партии в строки, сохраняя исходный адрес каждой ячейки.
6. Не считать скрытые столбцы и листы несуществующими. Внешние кэши книги инвентаризировать отдельно; по умолчанию это зависимости исходника, а не дополнительные товарные факты.
7. Сохранять исходный знак операций. Очистка для прогноза выполняется отдельным шагом с объяснением.
8. Не суммировать повторные источники одного факта и не прибавлять итог к его детализации.
9. Не считать месяцы с нулевым начальным остатком полными месяцами отсутствия товара. Для stockout нужна отдельная методика и подтверждение.
10. Неполный сентябрь 2026 и известные ошибки формул должны быть видны в метаданных и проверках.
11. Кеш формулы хранить как сохранённый результат Excel, не как доказательство корректного пересчёта. Формулу, метод сервиса и итог сервиса хранить раздельно.
12. Для количества заказа использовать подтверждённые единицы, нормативы и определения свободного остатка. Не назначать отсутствующие сроки, валюту, вес и категории без явного источника или помеченного допущения.

## 12. Связь с текущим прототипом

`prototype/order_prototype.py` сейчас читает сводный `TDSheet` и отдельный MOQ. Он не реализует полный импорт всех файлов в БД. Описанные в `docs/design.md` сроки 60/30 дней, классы ABC/XYZ и другие параметры — проектные решения или расчёты, а не дополнительные Excel-поля.

Этот словарь ориентирован на весь предоставленный набор, чтобы будущий импорт мог сохранить и использовать динамику, историю остатков, сезонные блоки и IEK, даже если первый расчёт строится только для Systeme Electric.
